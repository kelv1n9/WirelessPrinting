# Ускорение передачи на карту принтера, 3 ноября 2026

До этих испытаний прошивка принтера использовала 115200 бод и пакеты по 96 байт. Замер сжатого G-code на ней дал 17,5 КБ/с. При попытках поднять скорость до 250000 и 500000 бод появлялись повторы и итоговая скорость падала. Marlin подтверждал пакет до записи на SD, поэтому ESP мог начать следующий пакет, пока принтер не читал UART.

Кандидат для испытания:

- Marlin сохраняет обычный `MAX_CMD_SIZE=96` и `BUFSIZE=32`. Для бинарного протокола выделено отдельно 1024 байта.
- Только USART3 получает приёмное кольцо 1280 байт. Глобальный `USART_RX_BUF_SIZE=256` не меняется.
- Подтверждение пакета `WRITE` отправляется после завершения записи на SD. Короткая запись считается ошибкой.
- `M575` разрешает 2000000 бод, загрузочная скорость остаётся 115200.
- ESP принимает размер пакета из `ss<sync>,<payload>,<version>` и может отправлять до 1024 байт. При сбое он запрашивает текущий номер, прерывает запись и закрывает бинарный режим.

Полный исходный дифф Marlin находится в [`patches/printer-speed.patch`](../patches/printer-speed.patch). Сборка `mks_robin_nano_v1v2_maple`: 61360 из 65536 байт статической RAM, 4176 байт остаётся для стека и динамических данных. Сборка `bare`: 53144 из 327680 байт статической RAM.

Модель с настоящим фрагментом Orca G-code длиной 39859 байт, повторённым до 996475 байт, UART 2000000, паузой записи 2 мс на пакет и дополнительной остановкой принтера на 5 мс каждые 50 мс: 3362 мс, 296 КБ/с, ноль повторов, файл на карте совпал побайтно. Это компьютерная модель, она не измеряет реальные задержки SD и качество провода. Одна только физическая скорость 2000000 бод даёт потолок 200000 сырых байт/с при 8N1; результат по исходному G-code выше благодаря сжатию heatshrink.

На принтере сборка от 3 ноября 2026 20:33:39 загрузилась после `M997`, что подтвердил `M115`. На этом экране Marlin скрывает `.bin` даже при `M20 F L`; файл прошивки проверяется через `M23`, который возвращает его имя и точный размер. Копия на карте ESP совпала с исходником по SHA-256.

Первый замер настоящего `Adil_PETG_29m50s.gcode`, 1010991 байт исходника, 477430 байт после сжатия:

|---:|---:|---:|---:|---:|---|
| 115200 | 1024 | 51.631 с | 19.6 КБ/с | 0 | полный файл на карте |
| 250000 | 1024 | 36.533 с | передача прервана | 41 | ошибка |

Повтор на 2000000 без опроса веба дал 29.348 с и 15 повторов. Таким образом, модельные 296 КБ/с на железе не достигнуты, и сетевой опрос не объясняет задержку. Диагностика в ESP теперь различает просьбы Marlin о повторе и отсутствие ответа до тайм-аута; следующий замер должен установить причину до дальнейшего изменения драйвера UART или записи SD.

Дополнение к кандидату: [`patches/printer-speed-diagnostics.patch`](../patches/printer-speed-diagnostics.patch) применяется после основного диффа. Оно выравнивает `binary_buffer` по 4 байтам, как требует `SDIO_WriteBlock`, и добавляет счётчики времени записи и обработки, читаемые через `M115`. В ELF диагностического образа до исправления буфер находился по `0x20003432`, после исправления по `0x20003434`. Отдельный контрольный сжатый G-code прошёл, а обычная передача `.bin` на установленной сборке отказала на первом блоке. Связь отказа с выравниванием требует проверки после установки.

Диагностический образ: 298996 байт, SHA-256 `3bcc61cb6a9eb39d1b0b9e1923fe61773c9bd75606cb5b71b152aedba93747bd`. Статическая RAM 61648/65536, остаток для стека и динамических данных 3888 байт. Полный образ сжат до 229095 байт и распакован настоящим декодером Marlin с побайтным сравнением под ASan/UBSan. Обычное обновление ESP дважды и затем повторно оборвалось через 27 секунд; причина пока не установлена. Для разовой установки исправленного Marlin проверен бинарный обмен через консоль ESP, позволяющий включить сжатие и для `.bin`.

ESP `83432a8` успешно установлен после штатного перезапуска модуля; HTTP 200 за 27.42 с, BootGuard confirmed в app0, резерв app1. Входящий UART-буфер увеличен с 256 до 2048 байт, что подтверждено `/api/status.link.rxBuffer`. На 2 Мбод длинные ответы теперь читаются целиком. Повтор файла: 33.866 с, 20 повторов, из них 12 запросил Marlin, 8 по истечении ожидания ответа ESP; последняя ошибка Marlin `Datastream timeout`. Обработка 5.543 с, вложенная SD 4.300 с. Увеличение входящего буфера ESP не устраняет аппаратные потери на приёмной стороне принтера.

Исправление восстановления OTA в ESP проверено компьютерными тестами на прерывание загрузки, ошибки begin/write/end, успешный повтор и освобождение TLS-мьютекса. Причина первоначального разрыва HTTP ещё не установлена; сама успешная загрузка после перезапуска не доказывает, что любой сетевой обрыв исключён.
